# 知识条目必填元数据规范

> 原则：字段宁少勿多，控制在维护者能稳定填写的数量。元数据不是装饰——它是权限控制、过期清理、AI 检索过滤的基础。

## 必填字段（每条知识条目）

| 字段 | 说明 | 示例 | 用途 |
|---|---|---|---|
| `title` | 条目标题，一句话说清内容 | "客户要求延长账期的处理规则" | 检索命中展示 |
| `module` | 所属模块（7 大模块之一） | 04 客户与沟通 | 蓝图对位、统计 |
| `submodule` | 所属子模块（34 之一） | 16 常见异议处理 | 分类导航 |
| `owner` | 唯一责任人（具体人/岗位，**禁止填部门**） | 销售部-张三 / 客户成功负责人 | 有效性问责、复审指派 |
| `scope` | 适用范围（谁/哪些业务可用） | 全体销售；仅 2B 大客户线 | 权限与场景过滤 |
| `classification` | 密级 | 公开 / 内部 / 受限（如价格、合同类） | 检索层权限过滤 |
| `effective_from` | 生效日期 | 2026-11-01 | 时效控制 |
| `expires_at` | 失效日期（长期有效则填"待复审"） | 2027-11-01 或 待复审 | 过期自动下架依据 |
| `source` | 来源文档/事件 | 《2026销售手册 v3》第4章 / 访谈：李四 2026-10 | 溯源、AI 引用回链 |
| `review_cycle` | 复审周期 | 年度 / 随版本 / 季度 / 半年 | 治理调度 |
| `last_reviewed` | 最近复审日期 + 结论 | 2026-10-15 继续有效 | 积压量统计 |

## 选填字段（按需）

| 字段 | 说明 |
|---|---|
| `related` | 关联条目/文档链接（建议 ≤5 个，防链接腐化） |
| `tags` | 自由标签 ≤3 个；高频搜索词优先入 tags |
| `status` | 有效 / 待复核 / 过期下架 / 归档保留（复审四结论） |

## 填写规则

1. `owner` 必须能落到一个具体的人或唯一岗位；填了部门名的条目视为不合格。
2. `classification` 与检索系统权限组一一对应，命名保持一致。
3. 无 `source` 的条目（来源不明的个人笔记）在清洗阶段标记待清理，不直接迁入。
4. 元数据在**建条目时**填写，不允许"先入库后补"——后补率超过 20% 说明字段过多，应删减。
