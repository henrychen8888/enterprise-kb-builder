# 判断力知识卡模板 + 结构化追问清单（第 7 模块专用）

> 用途：把老员工的隐性判断萃取成可检索、可被 AI 引用的知识卡。这是知识库价值密度的决定项。
> 铁律：**围绕真实决策事件追问，绝不泛泛记"经验总结"**。产出不是访谈稿，是卡。

## 一、萃取流程（关键事件访谈）

1. 选一位老员工**近期**做出的一个有代表性的判断。示例：
   - 某客户是否接受特殊账期
   - 某项目风险是否值得冒
   - 某竞品动作是否需要跟进
   - 某个"看起来正常的订单"该不该卡住
2. 按下方追问清单逐维追问（一次访谈 2–3 个事件，宁精勿滥）。
3. 访谈中受访者讲成故事时，拉回五维框架。
4. 当场填卡初稿，**回访确认**后入库并署名责任人——名字被准确引用，是老员工持续贡献的前提。

## 二、结构化追问清单（五维）

| 维度 | 问法 | 追问要点 |
|---|---|---|
| ① 信号 | "当时你看到了什么，让你开始往这个方向想？" | 具体到信息源：某句话/某个数字/某个异常。追"如果没看到这个会怎样" |
| ② 备选 | "你还考虑过哪些做法？" | 不只问最终选择；逼出至少 2 个被考虑过的方案 |
| ③ 排除 | "为什么最后没选那个？" | **信息量最大的维度**。每个被放弃方案的放弃原因都要记录 |
| ④ 边界 | "什么情况下这个判断就不成立了？" | 数值阈值、前提条件、触发回退的信号 |
| ⑤ 压缩 | "如果新人只记住一句话，是哪句？" | 压成一条可检索的判断规则；允许口语，但要自包含 |

## 三、判断力知识卡模板

```markdown
# 【判断力卡】<场景名：什么时候需要做这个判断>

- 模块：07 员工判断力　子模块：<33 岗位核心决策经验 / 34 判断规则>
- 判断人（责任人）：<姓名 + 岗位>　萃取日期：<YYYY-MM-DD>
- 来源事件：<一句话描述真实事件（已脱敏）>　复审周期：半年

## 场景
<一线员工在什么情境下会遇到这个判断点。>

## 信号
看到这些信号时，触发本判断：
- <信号 1：具体、可观察>
- <信号 2>

## 判断规则（新人只记一句话）
<压缩后的规则，自包含、可执行。>

## 判断过程（备选与排除）
- 备选 A：<方案> → 未选原因：<...>
- 备选 B：<方案> → 未选原因：<...>
- 实际选择：<...> 及依据

## 边界条件
- 本规则适用：<前提>
- 本规则不适用/需升级：<条件 → 升级给谁>

## 反例与例外
<历史上判断错的一次或差点错的一次：错在哪、后来怎么改的规则。>

## 复审记录（半年一复审 + 新案例增补例外）
| 日期 | 结论 | 复审人 | 新增例外 |
|---|---|---|---|
```

## 四、质量自检（入库前过一遍）

- [ ] 每张卡对应一个真实事件，不是"我觉得""一般来说"
- [ ] 排除原因至少记录 1 条被放弃方案
- [ ] 边界条件包含至少一个"不适用/需升级"情形
- [ ] 判断规则一句话可独立读懂（不依赖读完全卡）
- [ ] 责任人已署名并确认内容准确
- [ ] 敏感客户/金额已脱敏，密级已标
