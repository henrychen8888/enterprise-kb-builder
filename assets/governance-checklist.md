# 治理检查表（生命周期 + 健康度）

> 治理必须在建设阶段嵌入，不是上线后补。本表用于建设期自检和运行期周检。

## 一、建设期准入自检（每条知识入库前）

| # | 检查项 | 不合格的后果 |
|---|---|---|
| 1 | 有唯一责任人（具体人/岗位，非部门） | 不准入库 |
| 2 | 元数据 11 个必填字段齐全（见 assets/metadata-schema.md） | 不准入库 |
| 3 | 来源可溯（源文档或访谈记录） | 标记待清理，不迁入 |
| 4 | 与现行制度无冲突（冲突旧版本已下架或明确标注新旧关系） | 先处理冲突再入库 |
| 5 | 密级已标，且与检索系统权限组对齐 | 不准入库 |
| 6 | 复审周期已定 | 不准入库 |

## 二、复审周期速查

| 内容类型 | 复审周期 | 触发方式 |
|---|---|---|
| 制度/合规类 | 年度 + 政策变更即触发 | 政策发布事件 |
| 产品/价格类 | 随版本更新 | 产品上线事件 |
| 客户案例/话术类 | 季度 | 日历触发 |
| 判断力知识卡 | 半年 + 新案例增补例外 | 日历触发 + 结项事件 |
| SOP/流程类 | 半年或流程变更即触发 | 流程修订事件 |

**复审不是"再看一遍"**：必须给出四选一结论——继续有效 / 修订 / 过期下架 / 归档保留，并记录到条目的复审表。

## 三、更新动作嵌入业务流程（触发点清单）

| 业务事件 | 自动触发的知识库动作 |
|---|---|
| 制度修订发布 | 对应条目进入"待复核"，通知责任人 |
| 产品版本上线 | 价格表、FAQ、卖点卡进入待复核 |
| 项目结项 | 经验文档归档 + 提示萃取判断卡（判断力卡模板） |
| 客户重大投诉/纠错反馈 | 对应话术/FAQ 卡进入待复核 |
| 员工离职/转岗 | 其名下条目 30 天内完成责任人交接 |

## 四、治理健康度：只看四个指标

| 指标 | 定义 | 建议阈值 | 采集频率 |
|---|---|---|---|
| 陈旧内容占比 | 超过复审周期未复审的条目 / 总条目 | < 10% | 周 |
| 待复核积压量 | 处于"待复核"状态超过 2 周的条目数 | < 20 条 | 周 |
| 纠错反馈处理时长 | 从被纠错到结论落地的中位时长 | ≤ 3 个工作日 | 周 |
| 核心场景问题覆盖率 | 核心业务场景能在库中找到可靠答案的比例 | ≥ 80% | 月 |

不追求复杂报表。四个指标每周贴在团队可见处，趋势比绝对值重要。

## 五、运行期周检清单

- [ ] 四指标已更新且无恶化
- [ ] 本周「无结果搜索词」已逐条定性：缺条目（排期补建）/ 有条目但检索不到（改标题/标签）
- [ ] 本周「被纠错内容」已闭环，责任人已知悉
- [ ] 触发点事件（发布/上线/结项）均已在知识库产生对应动作
- [ ] 离职/转岗人员的条目责任人已交接
