# 分阶段实施路径

> 原则：不一次性铺满 34 个模块。选一个高频痛点明确的域 → 跑通全流程 → 再扩展。
> 里程碑均为建议值，按企业规模与人力调整；每个阶段有明确的"过/不过"验收标准。

## 阶段一：选定 MVP 域（2–4 周）

**做什么**
- 从 7 大模块中选 1 个使用频率高、痛点集中、知识来源明确的域作为试点。常见选择：
  - 「03 企业与产品」：产品 FAQ、价格体系、核心卖点
  - 「04 客户与沟通」：高频异议处理、销售话术
- 启动第一轮老员工判断力萃取：**哪怕只产出 5–10 张判断卡，也要在 MVP 中跑通"隐性知识入库"流程**。

**验收标准**
- [ ] 试点域的三态对位表完成（✅/🟡/⬜）
- [ ] 首批 30–100 条知识条目完成拆分（不是传文件）
- [ ] 5–10 张判断力知识卡入库
- [ ] 每条知识有唯一责任人

## 阶段二：建模与冷启动（4–6 周）

**做什么**
- 完成 MVP 域知识条目拆分、元数据填写、责任人指定。
- 数据清洗：剔除过期版本、冲突内容、无责任人的个人笔记。
- 若接 AI 检索：完成切片策略与混合检索联调。

**验收标准**
- [ ] 元数据完整率 ≥ 95%（用 assets/metadata-schema.md 校验）
- [ ] 与现行制度冲突的旧文档已标记待清理或下架
- [ ] 检索测试：20 个种子问题，15 个以上能命中正确条目
- [ ] 若接 RAG：表格类内容已转文字/QA 对

## 阶段三：试点与度量（6–8 周）

**做什么**
- 在选定部门/场景真实使用。重点不是"内容全不全"，而是**核心场景问题能否找到可靠答案**。
- 收集「无结果搜索词」和「被纠错内容」，每周清理并反馈责任人。
- 若引入 AI，用真实问题集测试四类：模糊问题、跨文档问题、权限边界问题、无答案问题。

**验收标准**
- [ ] 核心场景问题覆盖率 ≥ 80%（治理四指标之一）
- [ ] 每周无结果搜索词有闭环处理记录
- [ ] 纠错反馈处理时长 ≤ 3 个工作日
- [ ] AI 测试：无答案问题能明确说"无依据"，不编造

## 阶段四：推广与固化（持续）

**做什么**
- 试点规则跑通后再扩展模块。**每扩展一个模块，同步落实该模块的责任人、复审周期和元数据规则**，不"先传上去再说"。
- 治理机制从第一天按"长期资产"运营，不是交付即封存。

**验收标准（每新模块）**
- [ ] 责任人指定且知悉职责
- [ ] 复审周期写入元数据
- [ ] 与业务流程的触发点（发布/结项/上线）已打通

## 常见失败模式（提前规避）

| 失败模式 | 信号 | 对策 |
|---|---|---|
| 资料仓库化 | 只传文件不拆条目，检索命中率低 | 强制知识卡拆分，MVP 阶段就验收 |
| 三个月死亡 | 上线后无复审记录、积压增长 | 治理规则在建设期嵌入，四指标周报 |
| AI 用旧制度答新问题 | 纠错集中在过期内容 | 阶段二清洗 + 生效/失效时间过滤 |
| 第 7 模块留空 | 判断类问题仍靠"找人问" | 判断卡纳入 MVP 验收项 |
| 传上去再说 | 新模块无责任人无复审 | 扩展模块的准入门槛制 |
